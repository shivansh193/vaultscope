# VaultScope labeled dataset

Real IPsec captures generated by the Stage 0 testbed. Deliverable 1 of the
problem statement.

Each capture is one IKEv2 tunnel between two strongSwan peers in Docker, with
one class of traffic pushed through it. Every capture has a JSON sibling
recording what was **configured** — ground truth, not anything a parser
recovered.

## Regenerating

The pcaps are not in git: they are large and reproducible. The labels are, so
the ground truth stays reviewable in a diff.

```bash
python scripts/generate_dataset.py --target 300 --duration 30 --parallel 4
```

Docker must be running. A full run takes roughly 40 minutes. It is resumable —
a cell whose pcap and label already exist is skipped, so an interrupted run
continues where it stopped.

## Naming

```
<mode>_<cipher>_<group>_(pfs|nopfs)_(ipv4|ipv6)__<class>.pcap
tunnel_aes256gcm_modp2048_pfs_ipv4__voip.pcap
```

## The matrix

| Dimension | Values |
|---|---|
| Mode | tunnel, transport |
| Cipher suite | AES-128-CBC+SHA256, AES-256-CBC+SHA256, AES-128-GCM, AES-256-GCM, 3DES-CBC+SHA1, DES-CBC+MD5 |
| DH group | MODP1024, MODP2048, ECP256 |
| PFS | on, off |
| IP version | IPv4, IPv6 |
| Traffic class | VoIP, Video, Web, Email, ICMP, Chat |

144 tunnel configurations. The run takes a stratified sample across them —
every cipher, group and PFS state appears in every traffic class, and the
remainder is filled at random under a fixed seed, so a run is reproducible.

The weak suites are in the matrix on purpose. DES, 3DES and MODP1024 are what
give the rule engine something to find; a dataset of uniformly healthy tunnels
would demonstrate nothing.

## Traffic generators

| Class | Generator | Real protocol? |
|---|---|---|
| VoIP | sipp, G.711-rate RTP | yes |
| Video | ffmpeg, H.264 over RTP | yes |
| Web | curl against nginx | yes |
| Email | swaks with base64 attachments over SMTP | yes |
| ICMP | ping | yes |
| Chat | scripted bursty sender | **no — substitution** |

## Label schema

```json
{
  "pcap": "tunnel_aes256gcm_modp2048_pfs_ipv4__voip.pcap",
  "traffic_class": "VoIP",
  "substitution": false,
  "generator": "sipp -- sipp UAC against a UAS, G.711-rate RTP media",
  "duration_sec": 30,
  "config": {
    "version": "IKEv2",
    "mode": "tunnel",
    "encryption": "AES-256-GCM",
    "integrity": "implicit",
    "dh_group": "MODP2048",
    "pfs_status": "enabled",
    "auth_method": "PSK",
    "ip_version": "IPv4",
    "ike_version": "IKEv2"
  },
  "harness_notes": ["..."],
  "captured_at": "2026-09-06T12:00:00Z",
  "testbed_commit": "86b85c2"
}
```

Field names and values reuse `core.models.IkeParams` vocabulary, so a label can
be compared against a parsed session with no translation in between. That
comparison is a test: `tests/dataset/test_dataset_class_balance.py::test_parsed_crypto_matches_the_ground_truth_label`.

## Disclosed limitations

Read these before quoting any accuracy number off this dataset.

1. **Chat is a substitution.** A real messaging client cannot run in an
   isolated lab, so the Chat class is a scripted generator reproducing the
   shape of chat traffic — short messages in bursts, long idle gaps. Every
   Chat label carries `"substitution": true`. Do not present Chat results as
   real messaging traffic.

2. **The dataset is lab-clean.** One tunnel, one traffic class, no competing
   flows, no background noise, no packet loss. Real networks have all four.
   Classifier accuracy measured here is an upper bound and will be lower in the
   field.

3. **Every session shows NAT-T.** Docker's bridge network NATs, so IKE lands on
   UDP 4500 and `nat_traversal` reads true on every capture. That is a property
   of the harness, not of the configuration under test. A model must not learn
   from it, and a report must not present it as a finding.

4. **Captures are 30 seconds, not the spec's 120.** The Stage 3 flow statistics
   are stable well inside 30 seconds, and 120s across 300 captures is ten hours
   of wall clock for no additional signal. Deliberate deviation from spec
   Section 8.

5. **IKEv2 only.** strongSwan's IKEv1 support is legacy and configuring it
   doubles the matrix. The parser's IKEv1 path is covered by synthetic fixtures
   in `tests/ike_parser/`, not by this dataset.
